# PRD (Global)

This directory contains the product + refactor plan shared across the entire app.

## Why we have PRDs here
- Prevent “tribal knowledge” from scattering across `docs/`.
- Make refactors safe by documenting the current behavior and the target contracts.
- Enable future clients (e.g. mobile) by turning UI flows into stable data contracts.

## First refactor focus
1. Sections + Events experience (invites + section activity feed + routing)
2. Profile visibility + profile routing
